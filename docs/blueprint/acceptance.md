# ماتریس پذیرش بلوپرینت

وضعیت: طرح آزمون، نه گزارش قبولی. معیارهای کسب‌وکار از سند محصول مشتق شده‌اند. Tها شناسهٔ شاهد هستند و وضعیت اجرا در فهرست کارها ثبت می‌شود.

| شناسه | سناریو | نتیجهٔ لازم | نوع شاهد |
| --- | --- | --- | --- |
| T01 | رقابت چند کانال روی آخرین صندلی | یک رزرو موفق؛ باقی پاسخ تعارض معتبر | چند اتصال مستقل PostgreSQL و بررسی ردیف قطعی |
| T02 | انتخاب چند صندلی با یک مورد ناموجود | هیچ بخش انتخاب تصاحب نشود | rollback و بررسی همهٔ صندلی‌ها |
| T03 | قطع پاسخ پس از موفقیت مرجع | استعلام یا تکرار همان کلید یک نتیجه برگرداند | fault injection در adapter و قرارداد طرف مقابل |
| T04 | انقضا، تمدید و ساعت نادرست مرورگر | زمان مرجع معتبر؛ تمدید ردشده در UI اعمال نشود | تست backend و مرورگر |
| T05 | callback جعلی و تکراری درگاه | بدون verify وجه پذیرفته نشود؛ با تکرار اثر دوباره نباشد | provider sandbox و ثبت‌های مالی |
| T06 | پرداخت موفق دیرهنگام | تصاحب جدید قطعی یا بازپرداخت؛ بدون جایگزینی پنهان | هم‌زمانی با خریدار دوم و بررسی شناسهٔ رزرو |
| T07 | دو دریافت موفق یا درخواست‌های هم‌زمان بازپرداخت | یک خرید؛ وجه اضافه پیگیری؛ برگشت بیش از دریافت رخ ندهد | قفل پرداخت و گزارش تخصیص |
| T08 | پروندهٔ باز نزدیک شروع برنامه | مسئول، جانشین، موعد و تشدید؛ عدم بستن مالی با گذشت زمان | کنترل زمان و رخدادهای بررسی |
| T09 | لغو یک بلیط از سفارش چندبلیطی | بقیه معتبر؛ سهم‌ها از snapshot و جمع دقیق | مثال مالی مصوب و وضعیت بلیط‌ها |
| T10 | ثبت و اصلاح مالی | توازن بدهکار/بستانکار؛ posted تغییر نکند؛ اصلاح معکوس | بررسی دیتابیس و سرویس مالی |
| T11 | دو آماده‌سازی تسویه و نتیجهٔ انتقال نامشخص | مانده دوبار تخصیص نیابد؛ مبلغ نامشخص دوباره پرداخت نشود | چند مسئول/اتصال و دفتر تخصیص |
| T12 | دسترسی مستقیم به شناسهٔ مرکز یا سفارش دیگر | رد سمت سرور و عدم افشای داده در فهرست/خروجی | آزمون مجوز API و گزارش |
| T13 | OTP تکراری، حدس، ورود و logout | سقف تلاش، مصرف یک‌بار، چرخش و ابطال نشست | آزمون auth و CSRF |
| T14 | QR جعلی، اسکن هم‌زمان، زمان یا محل نادرست و لغو هم‌زمان | فقط پذیرش مجاز واحد ثبت شود | آزمون دستگاه/مرورگر و دیتابیس |
| T15 | crash بین commit و ارسال، پیام تکراری یا خارج ترتیب | بازدریافت، اثر یکتا و snapshot برای شکاف | restart worker، broker و provider آزمایشی |
| T16 | موبایل فارسی، نقشه و وضعیت خطا | خرید و پیگیری قابل انجام؛ تفاوت فقط رنگ نباشد | Playwright و بررسی دستی دسترس‌پذیری |
| T17 | restore قدیمی پس از فروش | قبل از تطبیق فروش باز نشود؛ ظرفیت مشکوک آزاد فرض نشود | تمرین restore و تطبیق درگاه/موجودی |
| T18 | شکست ارتقا پس از دریافت رخداد | دادهٔ جدید گم نشود؛ مسیر rollback/forward-fix روشن | مهاجرت روی دادهٔ آزمون و رخداد دیرهنگام |
| T19 | نصب مستقل و پایان پشتیبانی | ادامهٔ استفادهٔ مجاز بدون سرویس تولیدکننده | نصب از صفر و قطع وابستگی کنترل‌شده |

## قواعد اجرا

- آزمون‌های رزرو، مالی و مجوز عملیاتی روی PostgreSQL انجام شوند.
- تعارض درست ظرفیت از خطای فنی جدا شمرده شود.
- نبود دسترسی به سرویس واقعی به‌عنوان محدودیت ثبت شود؛ mock جای تأیید قرارداد واقعی را نمی‌گیرد.
- آزمون بار و زمان پاسخ از بخش ۱۶.۵ سند محصول پیروی می‌کند؛ اعداد هدف تا D12 مصوب نیستند.
- نتیجهٔ هر آزمون: نسخهٔ برنامه، محیط، داده، مراحل، انتظار، مشاهده و پیوند شواهد.
- شکست صحت مالی یا فروش تکراری، مانع عرضه است و با متوسط زمان پاسخ خوب جبران نمی‌شود.
