# گزارش بررسی هستهٔ مرجع ۰.۲.۰

محیط اجرای این گزارش: Python 3.14.7 روی Windows، SQLite محلی. این گزارش، تأیید PostgreSQL یا محصول عملیاتی نیست.

## نتیجه

- ۳۴ آزمون موفق، بدون شکست؛ زمان ثبت‌شده در test-results.txt برابر ۷۵٫۷۸۲ ثانیه.
- ۲۵ آزمون پایه حفظ و با API جدید سازگار شده‌اند.
- ۹ regression مستقل اضافه شده‌اند:
  ۱. لغو پیش از موعد تسویه و پس از عبور موعد، ماندهٔ کاذب نمی‌سازد.
  ۲. رد ظرفیت با همان کلید بعد از آزادشدن نیز replay می‌شود.
  ۳. کلید یکسان دو buyer در یک کانال، تداخل ندارد.
  ۴. buyer دیگر در همان کانال نمی‌تواند release/extend/create_order کند.
  ۵. inventory با اتصال query-only و رزرو منقضی نیز بدون تغییر داده کار می‌کند.
  ۶. باقی‌ماندهٔ کسری ریال به اپراتور می‌رسد.
  ۷. موعد از پایان و مهلت لغو، نه شروع، محاسبه می‌شود.
  ۸. redeem با actor و key یکسان موفقیت قبلی را برمی‌گرداند.
  ۹. schema قدیمی بدون حذف یا حدس داده رد می‌شود.
- اجرای demo نسخهٔ جدید، دو بلیط برای خرید آزمایشی صادر کرد.
- ابزار check_docs، ۳۲ ردیف دامنه، ۴۱ سناریوی محصول، ۳۶ کار، ۴۷ سناریوی پذیرش و ۲۳ تصمیم فنی را بررسی کرد؛ لینک‌ها، نگاشت‌ها و گراف وابستگی معتبرند.

## حدود شاهد

۴۷ T، برنامهٔ پذیرش محصول‌اند، نه ۴۷ آزمون اجراشده. maker-checker، quota PostgreSQL، clock_timestamp بعد قفل، provider واقعی، QR امضاشده، rate limit، تخفیف و backup عملیاتی هنوز پیاده و تأیید نشده‌اند.

تفاوت زمان اجرا با محیط‌های دیگر معیار کارایی محصول نیست. آزمون‌های رقابتی نمونه فقط صحت همین پیاده‌سازی SQLite را می‌سنجند.
