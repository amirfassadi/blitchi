# ماتریس مجوز پیشنهادی

وضعیت: پیش‌نویس؛ مرجع محصول بخش ۶. پیاده‌سازی مجوز هنوز در نمونهٔ مرجع موجود نیست.

## نقش‌ها

خریدار، مسئول ورودی، کارکنان مرکز، مدیر مرکز، کارکنان محتوای اپراتور، پشتیبانی اپراتور، مسئول مالی اپراتور و مدیر اصلی. عضویت و مجوز به مرکز/محل مشخص محدود می‌شود. نقش مالی و دسترسی حساس جداگانه اعطا می‌شوند.

| عمل | مجوز و محدوده |
| --- | --- |
| دیدن محتوای منتشرشده و موجودی بدون اطلاعات شخصی | عمومی |
| رزرو | نشست مهمان معتبر یا خریدار؛ سقف و مالکیت |
| سفارش و پرداخت | خریدار همان سفارش؛ مبلغ از سرور |
| دیدن سفارش و بلیط | خریدار خودش؛ پشتیبان در محدودهٔ مسئولیت با ثبت دسترسی |
| درخواست لغو | خریدار سفارش خودش یا کارمند دارای مجوز صریح |
| دیدن فهرست مراجعه‌کنندگان | کارمند مجاز همان مرکز/برنامه با حداقل اطلاعات |
| validate و redeem | مسئول ورودی دارای مجوز محل و پنجرهٔ زمانی |
| تعریف برنامه و قیمت | مرکز خودش با اجازهٔ اپراتور؛ انتشار تابع D09 |
| تأیید انتشار | کارمند محتوای اپراتور با مجوز مربوط |
| دیدن صورت‌حساب مرکز | مدیر همان مرکز؛ مالی اپراتور در محدودهٔ وظیفه |
| آماده‌سازی تسویه | مجوز مالی مستقل؛ مرکز و ماندهٔ مجاز |
| تأیید تسویه یا بازپرداخت | مجوز تأیید مالی مستقل؛ هویت مجدد طبق سیاست |
| ثبت نتیجهٔ انتقال | مجوز ثبت مدرک مالی و کنترل رسید یکتا |
| تغییر کمیسیون یا حساب بانکی | مجوز حساس مستقل، تأیید هویت و ثبت تاریخچه |
| دیدن کامل حساب بانکی | مجوز صریح؛ پیش‌فرض نمایش پوشانده |
| تخصیص پروندهٔ بررسی | مسئول عملیات یا ناظر؛ قابل واگذاری با سابقه |
| خروجی اطلاعات شخصی یا مالی | مجوز خروجی جدا، scope و ثبت عملیات |
| مدیریت اعضا و اعطای مجوز | مدیر مجاز؛ نتواند مجوزی فراتر از اختیار خود اعطا کند |
| دسترسی کانال بیرونی | هویت ماشینی و scopes همان کانال؛ نه نقش کاربری مرورگر |
| مشاهده/لغو فروش کانال دیگر | ممنوع مگر مجوز مدیریتی صریح و قرارداد معتبر |

## قواعد اجباری

- بررسی مجوز در endpoint و سرویس دامنه؛ مخفی‌بودن دکمه کافی نیست.
- فهرست، جست‌وجو، export، فایل ضمیمه و پیام خطا نیز scope داشته باشند.
- شناسهٔ قابل حدس یا غیرقابل حدس به‌تنهایی مالکیت ایجاد نمی‌کند.
- مجوز کارکنان لغوشده باید روی نشست و فرمان‌های جدید اعمال شود.
- ورودی actor، center_id یا channel_id ارسالی کاربر جای هویت معتبر را نمی‌گیرد.
- خطای دسترسی نباید وجود سفارش یا اطلاعات شخصی مرکز دیگر را افشا کند.
- عملیات حساس در audit بدون کپی‌کردن رمز یا اطلاعات بانکی کامل ثبت شود.
- مدیر مرکز مجوز حذف سند مالی قطعی یا تغییر دستی وضعیت تراکنش ندارد.
- جدایی آماده‌ساز و تأییدکننده برای تسویه و بازپرداخت قاعدهٔ پایه است؛ هیچ actor درخواست خودش را تأیید نمی‌کند. حد نصاب امضای اضافه برای مبالغ بزرگ تصمیم جداست. پیاده‌سازی این قاعده در هستهٔ مرجع هنوز وجود ندارد.
- دسترسی تولیدکننده برای پشتیبانی دائمی و نامحدود فرض نمی‌شود؛ با رضایت و scope موقت ثبت شود.

## آزمون

برای هر نقش، آزمون مثبت در scope خودش و آزمون منفی روی مرکز، سفارش و فایل دیگر لازم است. خریدار B روی رزرو خریدار A در همان کانال وب، replay کلید actor دیگر، تغییر نقش در نشست باز، API مستقیم، batch/export و حدس شناسه نیز بررسی شوند. آزمون‌ها به T12 تا T14 بلوپرینت وصل‌اند.
